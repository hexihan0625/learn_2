# 任务 2：合成旋转视频的参数拟合结果

## 1. 任务目标

输入一段合成旋转视频（青色目标绕固定中心匀速旋转，转速周期性起伏），
程序需完成四件事：

1. 逐帧检测青色目标，得到其像素中心；
2. 由像素中心反算旋转**角度**，并展开为连续角度序列；
3. 用非线性最小二乘拟合出角度模型中的 5 个参数；
4. 输出拟合对比图、残差图、角速度图，以及带标注的合成视频。

## 2. 数学模型

### 2.1 角速度模型

目标的瞬时角速度随时间作正弦起伏：

```
omega(t) = b + A * sin(Omega * t + phi)
```

其中 `b` 为平均角速度，`A` 为角速度起伏振幅，`Omega` 为起伏的角频率，`phi` 为初相位。

### 2.2 角度模型

对 `omega(t)` 积分，得到实际用于拟合的角度表达式：

```
theta(t) = theta0 + b * t - (A / Omega) * cos(Omega * t + phi)
```

其中 `theta0` 为初始角度。求导即可验证二者关系：
`d(theta)/dt = b + A * sin(Omega * t + phi) = omega(t)`。

### 2.3 角度定义与展开

图像坐标系 `x` 向右、`y` 向下。以画面中心 `(cx, cy) = (480, 360)` 为旋转中心，
从 `+x` 方向起算、逆时针为正：

```
theta_wrapped = atan2(cy - y, x - cx)        // 取值范围 (-pi, pi]
```

由于 `atan2` 输出在 `(-pi, pi]` 间跳变，视频总转角超过一圈（实测约 5.24 圈），
必须**逐帧展开**：将相邻两帧的角差规范到 `(-pi, pi)` 后再累加，得到单调连续的 `theta(t)`。
展开前的跳变若不处理，拟合将完全失效。

## 3. 求解方法

### 3.1 总体流程

```
读视频 → 逐帧检测青色质心 → 反算并展开角度
      → 线性拟合 + DFT 扫描得初值 → Ceres 自动求导精修 → 计算误差与出图
```

### 3.2 初值估计（本任务的关键）

非线性优化对初值敏感，`Omega` 初值偏差会直接导致落入"高频病态解"（把噪声拟合成正弦）。
因此不采用随机或经验初值，而是分三步解析求解：

| 步骤 | 做法 | 得到 |
| ---- | ---- | ---- |
| ① 线性趋势 | 对 `theta(t)` 做 `theta ≈ b*t + c` 的最小二乘拟合（Eigen `colPivHouseholderQr`） | `b`、截距 `c` |
| ② 频率扫描 | 对去趋势残差 `detr = theta - (b*t + c)` 做 DFT 幅值扫描，取幅值峰值频率 | `Omega` |
| ③ 振幅反推 | 由残差振幅 `0.5*(max-min) ≈ A/Omega`，反推 | `A` |

其中**频率扫描**在 `[pi/span, pi/(2*dt)]` 上做对数均匀采样（4000 点）：
下界对应"整个视频只转半圈"，上界为采样定理限制的 Nyquist 频率，防止出现超过采样能力的虚假高频解。

### 3.3 非线性优化

- **优化器**：Ceres Solver，自动求导（`AutoDiffCostFunction`，代价函数模板化以支持 `Jet` 对偶数）；
- **残差**：`residual = theta_model(t) - theta_observed`，共 1440 个残差块；
- **线性求解器**：`DENSE_QR`（参数仅 5 维，属小规模稠密问题，QR 稳定且足够快）；
- **损失函数**：`nullptr`（标准最小二乘；若观测含离群点可换 `HuberLoss`）。

### 3.4 参数约束

依据物理意义设置边界，避免无意义解：

| 参数 | 约束 | 理由 |
| ---- | ---- | ---- |
| `A` | `A > 0` | 振幅取正，正负号交由相位 `phi` 吸收 |
| `Omega` | `Omega ∈ [pi/span, pi/(2*dt)]` | 下界防"过慢解"，上界即 Nyquist 频率防"虚假高频解" |

### 3.5 收敛情况

```
Ceres Solver Report: Iterations: 5, Initial cost: 1.723390e+01,
Final cost: 3.986972e-03, Termination: CONVERGENCE
```

初值估计充分接近真解，仅 5 次迭代即收敛，代价从 `1.72e+01` 降至 `3.99e-03`。

## 4. 拟合参数

| 参数 | 符号 | 估计值 | 单位 | 含义 |
| ---- | ---- | ------ | ---- | ---- |
| 初始角度 | `theta0` | 0.604621 | rad | t=0 时的角度 |
| 平均角速度 | `b` | 1.350030 | rad/s | 旋转的平均快慢 |
| 角速度振幅 | `A` | 0.549935 | rad/s | 转速起伏的幅度 |
| 起伏角频率 | `Omega` | 1.649870 | rad/s | 转速起伏的快慢 |
| 初相位 | `phi` | 0.702902 | rad | 归一化至 `(-pi, pi]` |

由 `Omega` 得角速度起伏周期：

```
T = 2 * pi / Omega = 3.80830 s
```

整段视频共记录到约 `5.238` 圈旋转，与 `b` 乘以总时长的一致性可作交叉验证。

## 5. 误差指标

| 指标 | 数值 | 说明 |
| ---- | ---- | ---- |
| SSE（残差平方和） | 0.00797394 | `sum((theta_fit - theta_obs)^2)` |
| RMSE（均方根误差） | 0.00235318 rad | `sqrt(SSE / N)` |
| RMSE（角度制） | 0.134827 deg | 换算后平均每帧角度误差 |
| 有效样本数 | 1440 / 1440 | 检测成功率 100% |
| 时间范围 | 0.000000 ~ 23.983333 s | 共 24 s |
| 求解状态 | 可用（Solution Usable） | `summary.IsSolutionUsable()` 为真 |

平均每帧角度误差约 **0.13°**，相对于整段 5 圈以上的总转角（约 1886°）而言，
相对误差约万分之一量级，说明模型与观测高度吻合。

## 8. 注意事项

- **中文字体**：OpenCV 的 `putText` 不支持中文，画面文字一律使用英文/数字，否则显示为方块。
- **颜色通道**：`cv::Scalar` 为 BGR 顺序，红色是 `(0, 0, 255)`、青色是 `(0, 255, 255)`，写反会导致画面颜色颠倒。
- **视频编码**：输出采用 `mp4v`（MPEG-4 Part 2）编码；若需在浏览器中直接预览，可转码为 H.264：

  ```bash
  ffmpeg -i result/task2_fit/tracking_overlay.mp4 -c:v libx264 -pix_fmt yuv420p result/task2_fit/tracking_overlay_h264.mp4
  ```

- **素材保护**：生成标注视频时输出路径不得与输入路径相同，代码中已加入检查，避免误覆盖原始素材。
